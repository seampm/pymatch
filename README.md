# pymatch

A limit order book matching engine in Python, plus an exchange simulator and an event-driven backtester.

**[Live demo](https://seampm.github.io/pymatch/)** — animated order book from a real simulated session.

## What it is

Every stock and crypto exchange runs on a matching engine: the system that pairs buyers with sellers under strict price-time priority. pymatch is a from-scratch implementation of that system:

- **Matching engine** (`pymatch/orderbook.py`) — limit/market orders, IOC/FOK time-in-force, cancel/replace, price-time priority matching. All money math in integer ticks; no floats near prices.
- **Exchange simulator** (`pymatch/exchange.py`) — wraps the book with network latency (orders execute at `t + latency`) and a full timestamped event log.
- **Backtester** (`pymatch/backtest.py`) — strategies trade against synthetic market flow with latency and maker/taker fees. Tracks cash, inventory, and a midprice-marked equity curve; reports Sharpe and max drawdown.
- **Example strategies** — an inventory-skewed market maker and a momentum taker, deliberately naive.

## Quickstart

```python
from pymatch import MarketConfig, MarketMaker, run_backtest

r = run_backtest(MarketMaker, MarketConfig(steps=5000, seed=7))
print("P&L:", r.final_cash_ticks, "ticks")
print("Sharpe:", round(r.sharpe(), 2))
print("Fills:", r.n_fills, "| maker fills:", r.n_maker_fills)
```

## Design notes

- **Integer ticks everywhere.** Prices and cash are ints; the midprice is the only float, used for marking only.
- **Price-time priority.** One side of the book is a `dict[price -> deque]`, with a bisect-maintained sorted price list. Bids read best-from-back, asks best-from-front.
- **The book never crosses.** Every order fully exhausts matchable liquidity before resting anything; `check_invariants()` asserts no crossed market, sorted price levels, and queue/map consistency. A randomized fuzz test hammers this.
- **Latency is honest.** Orders scheduled through the exchange execute at `t + latency_ns` in a heap queue; a strategy quoting on stale data gets adversely selected — which is exactly what happens to the example market maker if you crank up volatility.
- **Deterministic.** Same seed, same results. The backtest suite asserts this.

## Honest limitations

- The market data is **synthetic** (Poisson quotes around a GBM midprice). It exists so strategies can be tested without a data license. Nothing here says anything about real markets.
- The example strategies are **deliberately naive baselines**, not trading advice. The market maker's edge is the spread; the momentum trader mostly pays fees.
- Throughput is good for Python but nowhere near a production C++ engine (which does millions of orders/sec). The hot path is the per-level matching loop.
- Single-threaded; no concurrency story yet.

## Layout

```
src/pymatch/
  order.py       Order, Side, OrderType, TimeInForce, engine events
  orderbook.py   Price-time priority matching engine
  exchange.py    Latency + event log wrapper
  market.py      Synthetic market data generator
  strategy.py    Strategy base class, MarketMaker, Momentum
  backtest.py    Event-driven backtester with portfolio accounting
tests/           23 tests: priority rules, TIF semantics, fuzz invariants, backtest determinism
bench/           Throughput benchmarks
demo/            GitHub Pages animated order book (session.json generated by gen_data.py)
```
